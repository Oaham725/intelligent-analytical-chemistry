# 2026–2027 学年传承题库

这里的题目由本届学生为下一届学生设计。题目不追求偏、怪或重复计算，而应检验一个能够迁移到真实分析问题的判断。每道题应在本页相应章节下添加：题目标题、题型、考查目标、题干、答案要点、所需数据/代码链接和贡献 PR。

## 题目质量要求

- **有对象**：给出足以作答的样品、测量条件、矩阵/谱图/图像或数据背景。
- **有判断**：不能只要求复述定义；应要求比较方法、识别假设、解释失败或完成推导。
- **有答案边界**：写出关键得分点与常见误区，而不是只放最终数值。
- **可传承**：不依赖已失效的临时网页、私人数据或本届课堂口头信息。

#### 传承题 17-1　显色样品的 MDP：什么时候“等下去”值得？

- **题型**：计算 + 判断
- **考查目标**：能写出 MDP 五元组；能做一步 Bellman 备份；理解奖励与折扣如何改变最优策略（第17章 17.2、17.3）。
- **数据/代码**：[`code/ch17_exercises/01_colorimetric_mdp.py`](https://github.com/Oaham725/intelligent-analytical-chemistry/blob/main/code/ch17_exercises/01_colorimetric_mdp.py)（可用来核对数值）。

**题干**：铁(II)–邻二氮菲显色测定中，单个样品的状态记为 $s=(c,r,d,u)$：浓度等级 $c\in\{低,高\}$、已加显色剂份数 $r$、显色进度 $d\in\{0,1,2\}$、是否已稀释 $u$。高浓度样品需 2 份试剂且必须稀释后报告才正确。动作与即时奖励：加试剂 −0.4、等待 −0.6、稀释 −1.0；报告正确 +10、报告错误 −10；$\gamma=0.95$。试剂充足时，“等待”以概率 0.75 使显色推进一级，否则停留原状态。

1. 计算 $Q^*((高,2,2,0),\text{稀释})$ 与 $Q^*((高,2,2,0),\text{报告})$，给出最优动作。
2. 假设在 $(高,2,1,0)$ 的最优动作是等待，写出 $V^*(高,2,1,0)$ 满足的方程并求解。
3. 若把“报告错误”的奖励从 −10 改为 0，且 $\gamma=0.6$，智能体从 $(高,0,0,0)$ 出发会怎么做？这说明了奖励设计中的什么问题？
4. 有同学主张把状态简化为“当前吸光度 $A$”。用一个具体反例说明这为什么破坏马尔可夫性。

**答案要点**：

1. $V^*(高,2,2,1)=10$，所以 $Q^*(\text{稀释})=-1.0+0.95\times10=8.50$；$Q^*(\text{报告})=-10$；最优动作为稀释。（若再算“加试剂”：$-0.4+0.95\times8.50=7.675$，仍不如稀释。）
2. $V=-0.6+0.95\,[0.75\times8.50+0.25\,V]$，即 $0.7625\,V=5.456$，$V^*\approx7.16$。
3. 最优策略变为“立即报告”（$V^*=0$），因为完成实验的折扣期望回报约为 −0.52，不如什么都不做。说明错误结果没有代价时，系统会“偷懒”；奖励必须表达分析结果错误的真实后果。
4. 两个孔都读到 $A=0.35$：一个刚加试剂（后续还会升高），一个已显色完全（不会再变）。状态相同、未来不同，故不是马尔可夫的；需加入“自加试剂以来的时间”或读数趋势。

**常见误区**：把 $V^*(高,2,2,1)$ 当成 0（忘了报告的终止奖励）；第 2 问中直接用 $V$ 代替期望；第 3 问只答“γ 太小”，没有指出惩罚为 0 才是根本原因。

**贡献 PR**：#编号（G17）

#### 传承题 17-2　“连续运行 72 小时”能说明什么？

- **题型**：评价 + 设计（开放题，有明确得分点）
- **考查目标**：区分硬约束与科学目标；用故障注入暴露静默错误；给出完整的自主平台评价指标（第17章 17.4、17.5、17.7）。
- **数据/代码**：[`code/ch17_exercises/03_fsm_fault_injection.py`](https://github.com/Oaham725/intelligent-analytical-chemistry/blob/main/code/ch17_exercises/03_fsm_fault_injection.py)。

**题干**：某课题组报告其自主比色平台“连续运行 72 小时、完成 600 个样品、零停机”。平台的控制程序在分液命令超时后会自动重发；没有体积传感器；每 50 个样品人工校准一次光谱仪；强化学习策略的奖励为“每小时完成样品数”。

1. 指出该平台设计中至少三个可能导致“静默错误”的环节，并说明各自的机理。
2. 为它设计一个故障注入测试矩阵（至少 4 类故障），写出注入方式、期望行为和检验依据。
3. 改写奖励函数，并列出应写进屏蔽器而不是奖励的两条硬约束。
4. 除“运行时长、样品数”外，评价报告还应包含哪些指标？各用什么方法获得？

**答案要点**：

1. （任三项）超时重发 → 确认帧丢失时重复分液；无体积传感器 → 气泡导致体积不足无法发现；固定周期校准 → 两次校准之间的灯源漂移无法发现；奖励为吞吐 → 策略倾向于跳过等待、空白与质控。“零停机”恰恰可能是因为不检查。
2. 参考第17章 17.7.4：气泡（吸入空气 → 体积核验 → 补差额）、应答丢失（软件丢弃确认帧 → 查询后不重复分液）、通信中断（拔 USB → 超时重连 → 安全态）、灯源漂移（中性滤光片 → 参比偏差超限 → 重新校准）、漏液（液位传感器 → 联锁安全态）、耗材耗尽。每项须写明检验所用的日志或盲样。
3. 奖励以质控样标定的浓度相对误差为主，扣除时间/试剂成本；硬约束如：孔内体积上限、未做空白不得测量、读数超出线性区不得报告、温度上限。理由：一次都不能违反的条件不应依赖权重“劝阻”。
4. 有效结果数与静默错误率（插入盲样/标准物质检出）、人工接管次数与平均间隔（接管日志）、每样品试剂与样品消耗、与人工操作的误差对比和跨日复现率（同一样品不同日期重复）。

**常见误区**：只回答“增加传感器”而不说明它检测哪种故障；把“读数 < 0.3 不得报告”这类科学判断写进屏蔽器；把吞吐当作可靠性的证据。
